# Compose 迁移状态

当前分支：`feature/compose-migration`

## 已迁移

- Compose 应用壳、底部导航、页面路由和返回状态。
- 首页信息流、搜索、收藏/稍后看、我的、个人动态和阅读中心。
- 设置主页面及显示、数值、播放、缓存等子页面。
- 详情入口由 Compose 壳承接，但正文、评论、官方表情、多图、原图和互动暂时回落到原生详情宿主，沿用已经稳定的渲染与手势链路；Compose 详情组件保留在隔离边界内，待达到同等行为后再切换。
- 云端签到、签到日志、排行榜、登录表单和相关状态页面。
- 主要页面的控制器、异步缓存恢复、请求序列保护和资源释放。

## 保留的兼容层

- `ImageViewerActivity`：仍负责原生图片查看、缩放和手势退出。
- `VideoPlayerActivity`：仍负责播放器和手表媒体控制。
- 验证码/登录 WebView、崩溃恢复页、部分旧 ROM 兼容页。
- Java 网络、缓存、解析、加密和设备参数代码。

这些代码不是 Compose 页面重复实现，而是当前设备兼容边界。迁移时先保证路由和状态不会丢失，再逐项替换媒体和 WebView 相关实现。

## 回退与验证

- 原生 View 基线：`feature/ui-v2-native-view`。
- 当前分支不修改版本号，保持 `2.18 / 221`。
- 代码提交前必须通过 `:app:lintDebug`、`:app:testDebugUnitTest` 和签名 Release 构建。
- 圆屏、方屏、低内存设备、图片手势和播放器仍需要真机验证；构建通过不等于这些交互已经验收。

## 2026-10-03 交互回归修复

- 首页搜索框作为列表首项滚动，不再固定在页面顶部；加载和空列表也保留搜索入口。
- 首页、我的、搜索、阅读库和常规设置的滑动预览使用当前页面数据；目标页面按路由保持同一组合身份，交接时不重新创建目标页面。
- 手指位移只更新绘制层，不在每一帧重新组合帖子列表；取消与提交共用方向和位移规则。
- 原生详情入口不先把 Compose 路由切成详情，保留真实来源页面；清除旧原生页面，避免旧页面覆盖返回预览。
- 原生详情返回预览沿用同一页面渲染器和缓存状态，保留来源列表位置。预览不触发分页、表冠滚动和账号资料请求。
- 我的账号资料由独立控制器静默刷新，恢复头像、用户名、ID、关注、粉丝、获赞和签名；退出登录、切换账号及关闭页面宿主后拒绝过期回调。
- 设置开关使用 36x22 的紧凑轨道和等比例滑块，整行仍可点击，保留开关语义。
- 页面渲染分离到 `ComposeRouteScreen`，账号状态和请求分离到 `ComposeProfileState` / `ComposeProfileController`，转场几何分离到 `ComposeSwipePresentation`。

验证边界：纯逻辑和结构测试覆盖账号刷新、回调失效、拖动方向、全宽移动及路由交接；缺少已连接设备，尚未验收真实触摸事件、掉帧、图片加载观感和圆屏可点击范围。不得据此将全量迁移标记为完成。
