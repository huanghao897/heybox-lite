# Compose 全量迁移计划与收尾

## 目标

在 `feature/compose-migration` 中完成主界面 UI 从 Java 动态 View 到 Kotlin + Compose 的迁移，业务与数据层保持稳定。媒体查看器、播放器和 WebView 继续作为独立兼容层，直到对应真机验证完成。

## 阶段顺序

1. **构建与设计系统基础**
   - 引入 Kotlin、Compose runtime/ui/foundation/animation。
   - 建立黑灰主题、尺寸体系、圆屏/方屏窗口信息和统一语义标签。
   - 增加 Compose 测试入口，不改变现有启动路径。

2. **应用 Shell 与导航**
   - 将顶部栏、底部导航、页面状态和动画等级迁移到 Compose。
   - 保留现有 Java `ShellScreenNavigator` 作为过渡适配器。
   - 先验证页面切换、右滑返回、退出确认和列表位置。

3. **设置与账号页面**
   - 迁移显示、内容与缓存、视频、关于、诊断、登录和个人页。
   - 将设置状态转换为不可变 `UiState` 与事件回调。

4. **信息流、搜索、收藏和阅读中心**
   - 迁移分页列表、卡片、搜索框、加载/空/错误状态和离线列表。
   - 保留现有分页、缓存和图片加载器，先通过适配器提供状态。

5. **帖子详情与评论**
   - 迁移正文、游戏卡片、文章/帖子/视频类型、评论层级和互动按钮。
   - 先保留 `ZoomImageView`、视频内核和图片缓存，通过 Compose 容器承载。

6. **图片、视频和手表输入**
   - 迁移图片查看器 UI、播放器控件、表冠/旋转表圈和圆屏手势。
   - 删除旧 View 仅在 OPPO Watch X2、小米 Watch 5、三星和方屏设备验证后进行。

7. **清理与发布验证**
   - 删除已无引用的原生页面。
   - 运行单测、Compose UI 测试、截图测试、Release 构建和签名校验。
   - 不修改版本号，不发布服务器，不创建 GitHub Release，除非用户另行要求。

## 当前完成状态

- 阶段 1 至 5 已完成：Compose 编译链、主题、Shell、导航、设置、账号、信息流、搜索、收藏、阅读中心、详情、评论、游戏卡片和签到页面已经接入主路由。
- 主页面的异步缓存恢复已移出组合函数，控制器拥有请求序列、关闭和回调生命周期。
- 阶段 6 的媒体查看器、播放器和验证码 WebView 暂不删除原生实现；这些部分需要圆屏、方屏、OPPO Watch X2、小米 Watch 5、三星和华为真机验证。
- 阶段 7 的清理只允许删除已确认无引用的代码，不以缩短文件行数为目标进行冒险重写。

## 风险控制

- 不把整个现有 View 树包成一个 `AndroidView` 作为迁移完成标志。
- 不在 Composable 中直接调用 API、读 Cookie 或写 SharedPreferences。
- 业务类继续由 Java 管理，Compose 只接受状态和事件。
- 任何 API 21 以下兼容问题都回退到原生分支处理，不在本分支伪装支持。
