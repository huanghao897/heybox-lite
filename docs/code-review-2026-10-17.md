## 签到服务端与客户端错误契约修正

用户追加授权后，核对并修改工作目录中的 `CheckinCenter` 源码，客户端同步消费明确错误码；保留旧响应的必要兼容，通用路由 404 不当成订单消失。

- 设备令牌失效为 `401/device_authorization_invalid`；配对密码错误、会员未开通或到期、功能未开放、任务不存在及任务正在运行分别处理，不因此清除有效设备授权。
- 订单详情保持 `200 + status`，包括 expired/failed/paid；订单不存在及他人订单统一为 `404/order_not_found`。
- 二维码接口先执行既有过期处理。过期付款入口为 `410/order_expired`，已付款或失败订单为 `409/order_not_pending`，临时缺码或渠道读码失败为 `503/payment_qr_unavailable`；客户端通过订单查询确认真实状态，不由二维码错误推断付款成功。
- 设备限流由滚动窗口内最早一条有效尝试计算剩余秒数，向上取整；JSON `retry_after` 与 `Retry-After` 头一致，到报告的窗口边界可恢复。IP/账号登录与注册仍使用现有保守窗口，不改配额次数。
- 不修改 billing/payments 的结算核心。回归直接检查权益表与账本，验证过期订单仍可接受已核实的迟到爱发电付款，重复确认不重复增加权益。
- 设备授权存储的临时 Keystore 故障保留密文，恢复后可重新读取；已验证 token 按完整密文缓存，当前请求回调不会因为重复读取 Keystore 暂时失败而被误当作旧请求。密文变化立即使旧缓存失效，按 token 比较清理不会误删新授权。
- 后端原本有大量未提交改动，本次编辑前保存原样文件，另生成仅本次 8 文件的补丁与 SHA-256 清单；不将既有服务端工作混入客户端提交，也不部署服务器。
