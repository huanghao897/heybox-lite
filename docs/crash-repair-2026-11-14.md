# 崩溃与图片交互修复（2026-11-14）

## 已确认的崩溃

- 用户日志为自动崩溃，版本 `2.19 (222)`。R8 mapping ID 与本地该版本 `mapping.txt` 一致。
- Retrace 将异常定位到 `ComposeDetailImages.kt` 正文图片分页的 key/item provider，实际异常为 `IndexOutOfBoundsException: Index 3 out of bounds for length 3`。代码存在图片列表更新后页数、分页状态与 `urls[page]` 闭包不同步的窗口；用四张缩为三张构造回归测试，修复前可观察到旧页状态残留，但没有在本地复现完全相同的异常堆栈。用户日志未记录变化前的完整图片列表，不将具体的四张到三张视为已采集事实。
- 将 URL 列表固化为当前 gallery 快照，并以结构内容作为 Compose key，使列表变化时分页器、页数及 URL 回调整体切换；相同图片列表的媒体设置重组仍保留当前页。

## 同批用户报告的交互问题

- 查看器双击缩放现在按系统“动画”设置做 160/240ms 动画；用户再次触摸、拖动、捏合或退出时取消未完成动画。关闭动画设置时仍立即缩放。
- 首张图片尚未完成请求时，关闭按钮、系统返回和向上/向下拖动退出仍可用；加载期间关闭会取消图片请求，迟到结果不能复活已销毁的页面。页面黑色背景仍等待预览图或首张位图，避免为了开放关闭操作而提前闪黑。
- 回复胶囊的可见样式恢复到原先 26dp 高、紧凑填充胶囊；外层保留较大的触控区域，不再把视觉胶囊拉成细长条。

## 评论链接跳转（2026-11-15）

- 之前 Compose 行内链接统一交给系统浏览器；没有 `data-link-type` 的裸官方协议链接还会在文本归一化时丢失操作信息。
- 参照本地官方反编译结果 `utils/k.java` 的 @用户链接生成方式、`HeyboxWebProtocolHandler.java` 的 `openUser` / `openLink` 分发，以及 `utils/p0.java` 的帖子网页路径处理，增加独立的 `OfficialContentLink` 解析器。
- 帖子分享、正文网址、旧社区帖子网址，以及包裹在 `open_inapp` 中的官方协议均通过现有详情加载入口打开；@用户与用户主页网址通过现有用户空间路由打开。一级评论和楼中楼共用此行为，支持返回原来的帖子与评论状态。
- 外部网站、抽奖等尚未提供应用内页面的网页仍使用原浏览器行为；不把任意含有 `link_id` 或 `user_id` 的网址误判为应用页面，不执行其他应用协议。
- 链接识别不增加网络请求，不改官方 API、登录凭据或版本号。测试使用离线资料与点击坐标，不对真实账号发起操作。
