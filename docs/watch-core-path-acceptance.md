# 手表核心路径验收清单

## 范围与证据

- 当前迭代只收敛**详情导航/状态**和**自定义表冠速度**；其余项目用于回归，不改变 UI、版本或依赖。
- 本清单依据 `ARCHITECTURE.md` 及实际 `app/src/test`、`app/src/androidTest` 源码核对。下文定义待验标准，不自动继承历史通过状态；本轮命令与实际结果单独记录在 `tasks/compose-migration-status.md`，没有记录的设备行为仍待验。
- 架构约束：详情数据、评论操作上下文与计时跟随当前路由条目；父子条目及异步完成状态不混用；离开详情不保留可用的旧帖写入上下文。暂停后的调度不得继续运行。圆屏正文保持可读宽度，固定控件分别适配上下圆弧，不以最窄圆弧压缩整页。
- 层级：**L** = 无 Robolectric 的逻辑测试；**R** = Robolectric 状态/Compose 行为/真实 View 渲染测试；**M** = 手表真机。类名均位于 `app/src/test/{java,kotlin}/com/ronan/heyboxlite/`，带 `RobolectricTestRunner` 的状态测试仍归 R，不能仅凭名称归 L。未列 L 表示未找到直接对应的纯逻辑用例。
- `androidTest` 当前只有 `CheckinCenterDeviceTestRunner` 和 `CrashRecoveryDeviceChecks`：前者检查签到授权、令牌存储及下载 HTTPS，后者检查原生固定行列表绘制。二者不覆盖下列完整交互，也不能替代 M；L/R 通过同样不代表 GPU、物理表冠、解码及系统返回已验收。

## 准入与记录

- 执行前固定同一候选 APK/代码标识，记录设备型号、系统/ROM、屏幕形态、分辨率 px、密度及逻辑尺寸 dp、物理表冠有无、WebView 状态、界面/文字/正文缩放和系统字体比例。不得把 dp 当 px 或混用页面坐标与局部位图坐标。
- 准备测试账号 A/B、可重复访问的长首页、长正文且有多条评论的父帖 P、作者 U 及其另一帖子 C；另备多图/长图、可保留缓存的帖子和可恢复的断网/慢网条件。记录帖子标识和阅读统计基线；不清空日常账号数据，不记录凭据。
- 每项均须分别走圆屏、方屏 M。缺设备、表冠、WebView 缺失环境或无法稳定触发迟到请求时，记“阻塞/未验证”及原因，不用模拟输入冒充硬件结果。异常环境只在可恢复的测试设备上准备。

| 屏幕分组 | 现有 R 用例中的配置示例 | M 检查重点 |
| --- | --- | --- |
| 圆屏 | `192x192dp`、`227x227dp`，`round-mdpi`；底部导航另有 `192dp-round-xhdpi` | 标题、固定操作及触点在圆内，正文不被整页过度收窄，底部内容可读可点 |
| 方屏 | `240x320dp-mdpi`；窄屏/大字 `160x240dp-mdpi` | 不误用圆屏留白，长文字换行、末项和操作可达；强制圆屏设置单独记为兼容变体 |

R 配置是已有覆盖示例，不表示每个类都覆盖全部尺寸/形态。**圆屏 M 待验，方屏 M 待验**；L/R 仅以本轮验证记录为准。执行时按 `项目 ID | L/R 本轮结果及用例 | 圆屏 M | 方屏 M | 设备/设置/证据/缺陷` 记录；无对应自动用例明确写“覆盖缺口”。

## 首页与表冠

### F1 首页下拉刷新后继续阅读
- 操作：列表顶端下拉越过阈值并松手，加载中再拉一次；完成后继续滚动。分别补短拉/反向拉回/取消、非顶端下拉、空响应和断网后重试变体。
- 可观测预期：内容随手指下移，仅有效松手触发一次刷新；取消或非顶端不刷新，忙时不重复；成功后提示与位移复位，空响应/失败保留原列表且可再次刷新，无永久加载头。
- 自动对应：L `ComposeFeedControllerTest`、`OfficialPullRefreshStateTest`；R `OfficialPullRefreshUiTest`（含圆屏渐进拖动、取消、同帧完成及闲置刷新头不阻塞 fling）。
- 仍需 M：两种屏幕实际拖动、甩动并断网重试；观察 GPU 动画、触摸跟手和结束后的首次滚动，不能只看请求成功。

### F2 滚到底部分页并从失败恢复
- 操作：长列表连续滚到加载边界，等待追加；下一页请求中继续滚动，断网使其失败，恢复网络后离开末端再滚回重试，继续至无更多内容。
- 可观测预期：忙时只有一个分页请求；追加去重且不替换既有卡片、点赞等状态或当前可见锚点；失败退出忙态、不自动重试成环，重试仍接续原页；重复页/结束后不反复预取，主动刷新可重新开始。
- 自动对应：L `FeedPagingStateTest`、`ComposeFeedControllerTest`；R `ComposeFeedScrollUiTest`（追加保锚点、静止视口重新判断、拒绝加载不循环）。
- 仍需 M：真实首页跨至少两次追加，比较追加前后首条可见帖子及其屏内偏移；用可用的脱敏请求日志核对重复请求/游标，无法观测则记录缺口。

### F3 长首页滚动、进入详情再回原位
- 操作：在长首页上下往返，停在一条可辨认的帖子，记录位置，进入详情阅读后返回，再继续上下滚动。
- 可观测预期：复用后的标题、摘要和图片不串卡、不空白；普通滚动不误刷新；返回原列表锚点，继续滚动仍响应，不因界面重绑跳顶。
- 自动对应：R `ComposeFeedScrollUiTest`（列表内往返、真实 View 复用及锚点）、`ComposeRouteResourcesTest`（首页列表状态所有权）；它们不等于完整 Activity 往返已测。
- 仍需 M：两种屏幕各往返三次，录下返回首帧和继续滚动；同时检查首页底部导航未遮住可点击内容。

### C1 自定义表冠速度保存、取消与生效
- 操作：打开“滚动速度”，用 `5%`、`100%`、`200%` 比较相同方向/近似相同刻度的滚动；直接输入超滑杆范围且非步长整数倍的 `501%` 并确定，退出设置再重开应用核对；另试取消、空值、`4` 和溢出值 `2147483648`，最后主动拖动滑杆回 `150%`。
- 可观测预期：有效值原样保存并用于实际滚动，低速小步可累计，反转及时；`501%` 不被静默回夹/取整，滑杆仍只展示常用范围，重新打开并直接确认不改值；取消/非法输入不改已保存值，主动拖杆才改为常用范围内值。速度不是线性距离承诺，也不要求不同设备每格移动相同 px。
- 自动对应：L `CrownScrollControllerTest`、`NumericSettingValueTest`（超范围换算/保留、溢出边界、解析和滑杆范围）；R `ComposeCrownSettingsUiTest`（真实设置入口确认/重挂载、非法输入及主动拖杆）、`CrownInputHandlerTest`（保存回读后处理 rotary 事件）、`ComposeWatchDialogRoundUiTest`（圆屏/窄方屏通用弹窗）。
- 仍需 M：应用进程重启、系统输入法及物理表冠全链路均待验；`ComposeCrownSettingsUiTest` 覆盖方屏及圆屏设置入口，但配置和模拟输入不等同于真实手表。新增用例和源码接线的存在均不代表本轮已执行通过。

### C2 表冠与手指交替，输入只作用于当前页
- 操作：首页连续小步/快速转动并反转，手指拖动后再转；进入详情，在正文和评论各转动，再离开详情并返回。
- 可观测预期：不丢小步、不被一次手指拖动永久阻断；只滚动可见页面，正文和评论位置互不覆盖；离开页面的积压输入不在返回时突然补滚，停用页面/返回预览不消费输入。
- 自动对应：L `CrownScrollControllerTest`；R `CrownInputHandlerTest`（禁用时事件交回系统）、`ComposeFeedRotaryUiTest`（累积、清理、拖动后恢复）、`ComposeDetailPagerUiTest`（当前页及 inactive）、`ComposeThemeScrollUiTest`（消费一次且不重组调色板消费者）。
- 仍需 M：真表冠慢转、连转、反转、触摸交替各做一轮，检查切页后的首个刻度；开关“表冠滚动”后核对禁用/重新启用，不能以 `offer()` 注入代替设备事件。

## 详情导航与状态

### D1 正文、评论页与来源页依次返回
- 操作：从首页打开 P，正文左滑到评论，滚动评论后右滑回正文；再次进评论，连续使用两次系统返回；另走正文右滑返回来源页的分支。
- 可观测预期：正文/评论是连续跟手的独立页，无空隙或误弹出路由；评论右滑或第一次系统返回只回正文，第二次才退出 P；正文右滑按原路返回，不依赖新增返回工具栏。
- 自动对应：R `ComposeDetailPagerUiTest`（手势所有权、硬件返回优先级、圆屏无工具栏）、`ComposeDetailHostPagerUiTest`（真实宿主和系统返回接线）。
- 仍需 M：圆/方屏分别验证系统按键/手势返回及应用右滑；观察滑动过程中和松手后画面，确认一次输入只完成一层返回。

### D2 父帖 -> 作者 -> 子帖 -> 多次返回
- 操作：P 正文与评论分别滚到可辨认位置，停在评论页；由当前页可达的作者头像进入 U（评论页用选定评论作者），滚动作者列表并打开 C，在 C 正文返回 U，再返回 P，随后依 D1 返回正文和首页；正文作者入口另走一轮，并增加一层“C -> 另一作者 -> 第三帖”复验。
- 可观测预期：逐层回到准确父节点，不跳过作者、不串正文/作者/评论、不形成重复返回帧；P 恢复原评论页及两页各自位置，作者列表也不跳顶；离开详情后的作者页不能继续持有旧帖操作上下文。
- 自动对应：L `ComposeNavigationStateTest`、`ContentNavigationHistoryTest`（基础栈）；R `ComposeDetailNavigationTest`、`ComposeRouteResourcesTest`、`ComposeDetailPagerUiTest`、`ComposeDetailHostPagerUiTest`、`ComposeDetailParentRefreshTest`（Compose 路径）；`NativeDetailNavigatorTest`（原生回退的三层详情、作者页和原首页返回、原分页器及位置、已挂载预览恢复和退出后的上下文释放）。均非完整真机链路。
- 仍需 M：两种屏幕按上述完整链路连续走三轮，对照每次标题/作者/锚点；在每层尝试取消一次未完成的返回拖动，再完整返回，观察预览与最终页面是否一致。

### D3 父帖刷新未完成时进入子帖再返回
- 操作：在慢网下打开有缓存的 P，缓存可读但刷新未结束时走 `P -> U -> C -> U -> P`；恢复网络等待终态。另用已完成刷新 P、仍加载中的 C 重做。
- 可观测预期：C 完成不错误地结束 P 的刷新；返回未完成 P 后仍能取得本次新内容或到达明确失败/可重试终态；已完成 P 不因 C 未完成而重复加载。迟到内容/回复只能归属原条目，不能覆盖当前帖。
- 自动对应：R `ComposeDetailRefreshStateTest`、`ComposeDetailParentRefreshTest`、`ComposeDetailNavigationTest.backgroundReplyCompletionBelongsOnlyToItsSavedEntry`；`ComposeDetailLoadCompletionTest` 检查解析未确认时不重复发布入场预览，`ComposeNativeDetailHandoffTest` 检查 Compose 接管后的原生迟到 HTTP/网页/排队发布隔离，不能替代上述实机时序检查。
- 仍需 M：用暖缓存和可恢复慢网分别制造两种时序，保留返回前后内容和加载终态证据；缓存画面可读不等于刷新完成，无法观测请求终态时记未验证。

### S1 记住阅读位置后退出并重进同帖
- 操作：开启记住详情位置，滚动 P 正文后返回首页，再打开 P；分别补关闭该设置、另一帖子及账号 B 打开同一 P 的对照。
- 可观测预期：开启后正文恢复所记锚点及偏移；关闭后不恢复持久化旧进度；不同帖子/账号不串位置。持久化正文进度与 D2 返回栈内的评论页/评论位置不是同一项承诺。
- 自动对应：R `ComposeDetailPositionTest`（按账号/帖子保存读取）、`ComposeRouteResourcesTest`（资源移除）、`ComposeDetailPagerUiTest`（返回栈及 saved-instance-state 的双列表恢复）；开关入口和完整退出重进仍需补验。
- 仍需 M：两种屏幕记录同一段文字及屏内偏移，对比返回首帧、缓存展示和网络刷新后位置；不要把进程重启后的评论页恢复当成已有持久化保证。

### T1 前后台切换只累计当前详情的前台阅读
- 操作：选未读 P 记录统计基线，待加载完成前台阅读 60 秒，切后台 120 秒，再前台阅读 60 秒；返回作者页停留 60 秒，再查统计。另检查仅加载中、尚无正文时切前后台。
- 可观测预期：P 时长增量约为两段前台合计的 120 秒，仅允许统计最小显示单位的舍入；后台、作者页及尚未加载的详情不计入旧帖；同一 P 不因恢复前台重复计篇，文章/帖子及话题归属正确；恢复后页面可继续滚动。
- 自动对应：R `MainActivityReadingLifecycleTest`（精确模拟前后台时间、未加载详情不复用原生旧帖、离开详情停止计时），不是实际系统调度结果。
- 仍需 M：圆/方设备用秒表记录，比较阅读统计增量；按统计显示单位记录允许的舍入误差，必要时用脱敏诊断核对毫秒，不能仅凭“有增加”判通过。

## 图片、显示与兼容

### I1 正文/评论图片切换、打开并回到阅读位置
- 操作：在 P 的内嵌多图中横滑至末张再继续横滑，点击当前图片打开查看器后返回；评论图片再走一次；补无图设置和图片加载失败变体。
- 可观测预期：内嵌图集始终拥有自己的横向手势，末张不误翻到评论或返回；打开的是当前所点原图及其缩略图来源，返回不改变正文/评论页和位置；无图时不请求/响应隐藏图片，加载失败仍可退出阅读。
- 自动对应：R `ComposeDetailPagerUiTest.nestedImagePagerKeepsItsOwnHorizontalGestureIncludingAtItsEnd`、`ComposeDetailImagesUiTest`、`ComposeDetailVisualUiTest`（评论图片操作）、`ImageViewerTransitionTest`（缩略图与坐标来源）。
- 仍需 M：两种屏幕实际网络图片/GIF、正文及评论来源各往返，观察切图、解码和退回首帧；上述用例中有替身图片/回调，不能代替真实解码。

### I2 查看器缩放、拖动与退图
- 操作：打开长图，连续三次双击走完两级放大再适配；捏合并拖动放大图，恢复适配后上下拉取消一次、完成一次退图；多图切换后再用系统返回。
- 可观测预期：放大级别及长图可读范围正确，放大后能平移，不误触页面返回；适配态短拉回弹、有效上下拉退图，取消后仍能操作；退图只关闭查看器。圆屏保留短捏合增益和自动原图行为，方屏保留手动原图设置/入口，不借此改 UI。
- 自动对应：L `ImageZoomPolicyTest`、`ImageDismissPolicyTest`（策略，非触摸集成）；R `ImageViewerTransitionTest`（取消/退出过渡）、`ImageViewerRoundOriginalTest`（圆/方原图策略、失败保预览及控件位置）。
- 仍需 M：圆/方各用真实双指、长图和多图完成全套，核对缩放焦点、平移边界、切图后状态及原阅读位置；真实手势所有权和 GPU 过渡仍是覆盖缺口。

### V1 缩放/大字设置后完成一次阅读往返
- 操作：从默认显示进入最小可选界面缩放，再组合应用文字 `1.4`、系统字体 `1.3` 和正文放大；走首页 -> P 正文 -> 评论 -> 返回设置，最后还原原值。设备不支持某比例时记录实际值。
- 可观测预期：缩放各应用一次，正文/一级评论沿用统一排版；标题、操作与底部导航不相互遮挡，末项可滚到可读/可点区域。圆屏上下控件在圆内而正文不过窄；方屏无额外圆弧压缩，设置变化后导航尺寸/图标/避让同步。
- 自动对应：R `ComposeThemeScaleTest`、`ComposeDetailTypographyUiTest`、`ComposeReadingSettingsUiTest`、`ComposeDetailVisualUiTest`、`ComposeBottomNavigationUiTest`（不同测试分别覆盖比例、排版和几何，不表示该组合全链路已测）。
- 仍需 M：两种屏幕按组合截图并点击最靠边的操作，检查换行、触点及系统字体实际效果；方屏补强制圆屏开/关，分别记录，不代替圆形硬件。

### W1 WebView 缺失时失败可恢复，阅读仍可返回
- 操作：使用已缺失/损坏 WebView 的测试 ROM，确认测试账号需要重新获取写令牌；读 P 后触发一次需要令牌的点赞等操作，关闭提示并返回，再尝试一次。普通 WebView 设备作对照。
- 可观测预期：缺失时明确提示“当前系统的 WebView 不可用，暂时无法完成此操作”，不崩溃、不永久忙等、不伪报写入成功；再次尝试可得到独立失败结果，正文及系统返回仍可用。
- 自动对应：R `WriteTokenProviderFailureTest`（缺失/原生加载失败回调一次、释放工作、可再试）；它只验证 provider，不证明界面提示与整页恢复链路。
- 仍需 M：圆/方形态分别记录实际 provider 状态、完整错误提示和返回操作；无该环境则阻塞，不通过卸载日常设备系统组件来凑结果。

## 会话切换

### A1 在读取/分页未完成时退出或切换账号
- 操作：A 的首页分页或搜索请求未完成时退出，登录 B；分别回首页和原搜索。另在 `P -> U -> C` 后切换，返回并重开同帖；补同账号重新认证。
- 可观测预期：旧请求/已解析待发布结果不写入新会话，也不结束新请求忙态；重载前保留首页现有位置但清除 A 的点赞/收藏/关注状态，B 使用新的首请求/游标，搜索词按当前流程重查；旧作者资源和详情操作上下文不复活，显示/阅读偏好保留，同账号重认证不重复启动请求。
- 自动对应：L `FeedPagingStateTest`、`ComposeFeedControllerTest`、`SessionStoreLogoutPolicyTest`；R `ComposeAccountSessionUiTest`、`ComposeRouteResourcesTest`、`NativeSessionContentResetTest`。详情多层栈内实际切换仍需完整 M。
- 仍需 M：圆/方用专用 A/B 账号和可恢复慢网制造迟到响应，对照账号标识、列表状态和可继续刷新的结果；新列表内容改变后不要求跨账号保留同一帖子像素位置。

### A2 写令牌/写操作未完成时切换账号
- 操作：A 在 P 上发起需刷新令牌的写操作，完成前切 B，再等待旧成功/失败回调；B 在另一测试帖主动操作一次，同账号刷新令牌作为对照。
- 可观测预期：旧令牌不进入 B、旧操作不借 B 身份重试，也不弹出旧结果；B 的主动操作按 B 会话处理。同账号刷新可正常重试并只交付一次结果。
- 自动对应：R `WriteTokenProviderSessionTest`、`WriteActionSessionTest`；前者验证令牌/资源释放，后者验证会话变化后不重试及不交付旧结果。
- 仍需 M：两种屏幕用可撤销的测试点赞及脱敏日志核对账号、目标帖和请求次数，随后清理测试操作；不能稳定触发令牌刷新/迟到回调时标未验证，不以普通切账号代替。
